# Safebox objects (notes, and more types later)

Status: **all ten types are built** (note, secret, link, checklist, place, contact, date, ticket, album, case: model, backend, tests, app). The six new ones were written without a frontend build or run: try them live.

## What it is
The safebox held only files. An item now has a `type`: `file` (everything from before, and the default) or an **object** with no stored file: `note` for now. The content of an object is a small JSON **payload** (a note: `{ v: 1, title, text }`, title up to 100 and text up to 8000 characters, at most 16 KB) that is locked on the device. The server cannot read it.

## How it is stored
- Same locking as a file (`docs/design/safebox-encryption.md`): a random key per item, the payload locked with it (AES-GCM, part `meta`), the key locked for every key in use of both friends (`enc.wraps`).
- For an object `enc.meta` (with `enc.metaIv`) is the whole locked payload, `enc.iv` is only a placeholder with the same value as `metaIv`, `enc.thumbIv` is null. No file is stored, no preview.
- The server sees only: `type`, `addedBy` (the owner), `createdAt`, `updatedAt`, `revision`, the size of the locked payload (`bytes`, which counts in the box limits) and the wraps. `name` is a placeholder; the title is inside the payload.
- Because recovery (by my other devices or by a friend) and a new key only read and write `enc.wraps`, objects are re-locked for a new key with no extra code.

## Backend (`functions/src/safebox.ts`, `box-encryption.ts`)
- `POST .../safebox/items` `{ type, enc }` creates an object. Checks: a known object type, the shape, the size, and that the key is locked for every key in use of both friends (`409` when the keys changed). Tells nobody: adding or changing an item (or a file) never makes a message. The button "Tell {friend} about this" in the header of every item page (`app-safebox-tell`) sends a REGULAR chat message (`ChatService.send`, locked like any message when both have a key; with its sound and push), "📦 In the safebox: Ticket – the title". Nothing special on the server. It can be pressed again after a later change.
- `PUT .../safebox/items/:id` `{ revision, metaIv, meta }` changes it. `revision` is the one the app started from; if the friend saved first the answer is `409` and the app reads it again. The wraps stay as they are.
- Delete is the same route as for a file. A note has nothing to download (404) and is not renamed (400).
- `canChange(item, uid)` decides who may change or delete an item: for now **both friends may change or delete any item**. `addedBy` is kept so a rule such as owner-only is one change in this function.
- Tests: `functions/test/safebox-objects.test.ts`.

## App
- `core/box-crypto.ts` (`sealNote`, `resealNote`, `openNote`), `core/safebox.service.ts` (`addNote`, `readNote`, `updateNote`; a note is opened when the box is read, its title is the name in the list and its first line the snippet).
- One list for files and notes (`safebox/`): a note shows a note icon, the title, the first line, who and when, and has Open/edit and Take out (no download, lock or rename). **New note** is a button beside the Add files icon.
- Pages (children of the friend page): `/friends/:id/safebox/note` (new) and `/friends/:id/safebox/note/:itemId` (read and change), `safebox-note/`: title, text, Cancel and Save, and an inline "Take it out of the safebox" question. A note is never saved unlocked: without both keys the page says what is missing. A `409` shows "your friend saved first" with **Load their version**.
- The file viewer (`safebox-view/`) steps only between files.

## Attachments, and the album
- **Attachments**: any object can have files attached (up to 10; an **album** up to 100 pictures and videos). An attachment is an ordinary encrypted file of the box (same locking, previews, viewer, recovery) with a plain `parentId` (the id of its object) on its item: the server needs it to delete the attachments with their object, to count them and to keep them out of the main list. It sends `POST .../safebox/encrypted?parent=<object id>`; the server checks that the parent exists and is an object, the limits, and (album) `kind: image`. An attachment makes no "added to the safebox" notice. Deleting an object deletes its attachments (entries, files, previews); one attachment can be taken out alone (the same `canChange` rule).
- App: the component `safebox-attachments/` is used by the note page and the object page: thumbnails or signs, name, a small x with an inline confirmation, **Add files** (**Add pictures and videos** in an album) and the **Image**, **Video** and **Voice** buttons that make a new one on the spot (no Voice in an album; a link, a secret and a checklist have no attachments). On an existing object a chosen file is sent at once; on a new one the files wait in the page and are sent after the object is saved (if one fails the new object opens so the rest can be added again). The list and badges hide attachments and show "📎 n" on the object; an album's badge shows its first picture. The viewer steps only through the attachments of the same object (or the files that have none), and Back goes to the object.
- **Case** (type `case`): for a matter with documents: a name, case number / reference (Copy), who it is with, a status (open, waiting for an answer, closed), an optional deadline (date and time, with the same "Remind me" as a date) and a summary / notes. Its documents are attachments (up to 30, `CASE_DOCUMENTS_MAX`). The list shows the status, the reference and the days to the deadline.
- **Album** (type `album`): a name, a note and its pictures and videos (`kind: image` or `video` only).
- Later: attach a file that is already in the box, move an attachment, swipe between a ticket's attachments inside the object page.

## The other seven types (secret, link, checklist, place, contact, date, ticket)
- The server knows only the type name (`SAFEBOX_OBJECT_TYPES`); the payload is `ObjectPayload` `{ v: 1, title, fields, items? }`: `fields` are text by name, `items` are the entries of a checklist. The fields of each type are in ONE table, `core/safebox-objects.ts` (`objectKinds()`): secret `value`, link `url`, place `address`, contact `phone` + `email`, date `date` (yyyy-mm-dd), all with an optional `note`.
- ONE page for all six: `safebox-object/`, routes `/friends/:id/safebox/new/:type` and `/friends/:id/safebox/object/:itemId`. A secret's value is hidden until Show; Copy beside the fields that can be copied; link opens only http/https (`safeUrl`); place opens a map search; contact has Call and Write an email; a checklist has tick boxes and a count; a date shows the days left in the list.
- The list line under the name is made by `summaryOf` (a secret shows nothing). The list has a **New** frame with a pill for each kind. Each pill has a **tick** at its right end: ticked = items of that kind are in the list (all on by default; the choice is the UI preference `boxHidden`, the kinds that are off; adding an item of a kind turns its tick on again). A file always shows.
- A ticket is what (the title), where, date, time, a seat / booking reference / code (Copy button) and a note; the list shows the date and time, the days left and the place. Only text: a ticket as a PDF or picture is a file in the same box.
- A checklist is saved as a whole: if both friends save at once the second gets the 409 "load their version", there is no merge by entry yet.
- **A place on the map** (`located` in the kind table): the place keeps an address and/or a position (`fields.lat`, `fields.lng`, locked like the rest). The page has a **map drawn by the app** (Leaflet + OpenStreetMap tiles, no key, no cost; Leaflet is loaded only when a place page opens, its CSS is in `angular.json`): the pin follows the position, a tap on the map or a drag of the pin sets it (the address is then filled in from OpenStreetMap's reverse lookup while it is empty or came from the map; an address you typed by hand stays), and the map is shown above the address. **Use my location** (browser / WebView geolocation; Android declares ACCESS_COARSE/FINE_LOCATION, iOS has NSLocationWhenInUseUsageDescription) and **Search for a place** (OpenStreetMap Nominatim, one lookup per tap) move the pin too. Opening a place item loads map tiles from tile.openstreetmap.org (they see the area, never what the item is called); a search or an address lookup sends the typed text or position to nominatim.openstreetmap.org. Open in Maps (Google) uses the position, else the address. Please keep to the OpenStreetMap usage policies (light use, attribution shown).
- **Date and time, and "remind me"** (date and ticket, `timed` in the kind table): date AND time are required. The list and the badges show when it is (`whenOf`) and the days left. "Remind me" (none / at the time / 15 min / 1, 2 hours / 1, 2 days / 1 week before; default 1 day; optional "remind my friend too") is kept inside the locked payload (`fields.remind`, `fields.remindBoth`). The app also sends the MOMENT (`remind: { at, both }` on `POST .../items` and `PUT .../items/:id`; absent = unchanged, null = none): the one thing about such an item the server knows. It is kept in `safebox-reminders/{connectionId}_{itemId}` (`at`, `targets`), deleted with the item or the friendship, and a moment already past is no reminder.
- **Sending**: the scheduled function `safeboxReminders` (`index.ts`, every 5 minutes, needs Cloud Scheduler / the Blaze plan; the emulator does not run it) calls `sendDueReminders` (`safebox-reminders.ts`): it deletes the due reminder, then pushes "⏰ A reminder from your safebox" (title = the friend's name, a normal message push, so the same sound and switches) that opens the item. The text cannot say what is due: the server cannot read it.

## Links between items
- Any item (a file, a note or any typed object) can be linked with any other. A link is a locked item of its own, type `relation`, with the payload `{ title: 'link', fields: { from, to } }` (the ids of the two items), locked for both friends like every object. The server only sees one more ciphertext: it cannot tell which items belong together. It is never shown in the list (`shown` leaves it out) and does not announce anything.
- The app reads all relations when the box is loaded (`SafeboxService.relations`); `linkedWith(friend, item)` gives the other end of every link that touches an item, so a link shows on BOTH items. `addLink` makes one, `removeLink` deletes the record, `remove` (taking an item out) deletes its links first.
- UI: the component `safebox-links/` (note page, object page, file page): chips with the linked items (tap = open, x = take the link away) and **Link to another item**, which opens the full-screen page `safebox-link/` (`/friends/:id/safebox/link/:itemId`): the other items of the box with a search field; a tap makes the link and goes back. Attachments are not offered (they belong to their object). A link to an item that was taken out is simply not shown.
- Limits: a relation counts as one of the 500 items of the box (an item with many links uses many).

## Standard and advanced kinds (New frame)
The New frame shows the **standard** kinds first: File, Note and Date (`STANDARD_KINDS` in `core/safebox-objects.ts`; the person's own arrangement, `boxKindLayout`, is kept in the browser's localStorage with the other UI preferences and wins over the standard). The rest (Secret, Link, Checklist, Album, Place, Contact, Case, Ticket) are behind a dashed **Hidden types** pill that opens and closes them. A kind that already has an item in the box counts as standard and stays in the first row. The page "Add a new item and link it" uses the same split (`splitKinds`). The tick that hides a kind from the list is unchanged.

### Arranging the New frame (hold and drag)
Hold a kind in the New frame (or press it with a mouse for a moment), then drag it onto another kind (it takes its place) or onto the **More types** button (it goes in there; dropping a kind from More onto the button, or onto a kind in the first group, brings it out). The arrangement is the UI preference `boxKindLayout` (`{ main, more }`, each in order; null = the standard split of `splitKinds`); `arrangeKinds` applies it, also on the "new linked item" page. The cards of the icon view use the same helper (`core/hold-drag.ts`, `HoldDrag`) to change the number order of the items.

### The "Due" flag in the search field
A flag inside the search field of the list shows only what is **due**: an item with a date (date, ticket, case, checklist deadline) is due from the start of its reminder period ("Remind me", the lead before the date and time; a date without a time counts as 09:00) or the start of its day, whichever is first, to the end of its day. `dueRange` (`core/safebox-objects.ts`) makes that range; the locked head of an item carries it as `due` (`BoxHead`), so the list needs no content to know it. Items made before heads had `due` are read once by `SafeboxService.loadDues` (one at a time, nothing kept). An item with "Don't remind me" (`fields.remind = 'none'`) is never due: `dueRange` gives null. The flag shows how many items are due.
